# 光传码面(CP_PROTO_OB,实验)

非 QR 的屏幕到摄像头格式:在 V40 二维码的占地(177 × 177 模块,外加静区)里放 6 × 4 个独立校验的数据矩形,让一次曝光里属于不同刷新时刻的区域能各自被收下。设计、仿真对照和取舍见仓库根目录的 `CodeTrans-Optical-Reference/README.md`(参考实现:`protocol.py`、`tile.c`、`acquire.py`)。本目录的 C 实现与参考实现**逐字节一致**(渲染、单元判读与状态码、冷启动定位的角点,见下文“验证”)。

需要 CodeTrans 接收端,标准扫码器和 decimen.app 读不了。

## 两种配置

| | 横带 `CP_OB_BANDS` | 分块 `CP_OB_TILES` |
|---|---:|---:|
| 独立单元 / 码面 | 6 条(每条 4 个矩形) | 24 块 |
| 单元内码 | 4 路交织 RS(140,132) | RS(140,124) |
| 单元载荷 | 512 B | 108 B |
| 每码面载荷 | 3072 B | 2592 B |
| 清单周期 | 每 16 次刷新 1 个单元 | 每 8 次刷新 1 个单元 |
| 首遍附加修复行 | 0 | 每组 2 行 |

清晰、正对时用横带;斜拍、撕裂线常斜穿多个区域时用分块。

## 线格式(小端)

- **码面布局**:白 = 1。导频为 xorshift32 PRBS(种子 0x73513251)每字节最低位;四角 7×7 方向标记;数据矩形 j 左上角 (7 + 41·(j mod 4), 2 + 29·⌊j/4⌋),40 × 28 模块;每个八位组占 4 × 2 模块(上排在先、高位在先),八位组 b 位于第 (b mod 10, ⌊b/10⌋) 个小方阵;矩形 j 的 140 个八位组异或 PRBS(0xa7135c01 ^ j)。横带配置把第 2–4 列与第 172–174 列的 6 × 2 组配置标记取反。
- **单元**:12 B 头(8 B 会话标签、u16 组号、u8 行号、u8 类型)+ 定长载荷,CRC-32C(0x82F63B78,初值 / 末异或全 1)覆盖头和载荷。类型 0x10 / 0x11 = 分块数据 / 清单,0x20 / 0x21 = 横带数据 / 清单。
- **内码**:GF(256),本原多项式 0x11d,α = 2,根从 α⁰ 起。先验 CRC,再硬判决 RS,最后把低置信字节作擦除重试一次(2e + s ≤ 校验字节数)。
- **清单**:组号 0xFFFF、行号 0,载荷 `"CTB1"` + u32 容器长度 + 32 B 容器 SHA-256,其余补零;会话标签 = 整份定长清单 SHA-256 的前 8 字节。
- **外码**:每组 ≤ 32 个源行;源行号 0..k−1,修复行号 32..255,源列 i、修复行 r 的系数为 (32 ⊕ i) / (r ⊕ i);任意 k 个不同合法行可解,r = 32 为纯异或。
- **轮播**:每批 48 组按行交织发系统行(分块再加两行修复),之后对全部组轮发 32 轮新修复行,循环时修复行号继续轮换。第 t 次刷新的逻辑槽 i 画在 (5i + 7t) mod L(L = 屏上单元总数,须与 5 互素,所以码数 1/2/3/4/6 都可以)。
- **载荷**:即 CPO1 容器本身(与 CodeTrans v1 相同),上限 64 MiB。

## 接收

1. `cp_ob_locate`:半分辨率暗像素 → 5×5 膨胀 + 3×3 闭运算 → 4 连通域(短边 ≥ 130 半分辨率像素、长宽比 ≥ 0.55、密度 ≥ 38 %)→ 最外侧暗像素得四角 → 单应性采样 → 导频相关选四个朝向之一(> 0.50)→ 以已知黑白边沿最小二乘修正四角 → 相关 > 0.68 才接受。需要可见的浅色静区。
2. `cp_ob_track`:用上一帧的四角直接修正(小幅移动),失锁再冷启动。
3. `cp_ob_sample` + `cp_rx_push_board`:每个矩形用四周已知模块估黑白电平逐模块判决;首轮通过率低于 85 % 时,对失败单元再做一次局部亮度均衡(平坦 / 锐化二选一,按导频误差)。光学处理不持有 `cp_rx` 的锁。
4. `rx.c`:清单到达前最多缓存 768 个已过 CRC 的单元;按会话标签、组、行去重,同一行号内容冲突即放弃该会话;每组收满 k 行即解,全部解出后验整容器 SHA-256,再走与 CodeTrans v1 相同的 CPO1 结果输出。会话与 RaptorQ / Decimen 共用“最多 2 个活跃会话”的预算。

| Android | 「发送到电脑」可选横带或分块，每次刷新生成 1–2 个完整码面；接收端在 `scanner.c` 中跟踪和搜索码面。 |

## 验证

- `cp_core_tests`:960 组内码错误 / 擦除组合、960 组外码取行组合;两种配置 × 7 种大小的丢包(12 %)、乱序、重复、中途加入回环;合成 1280 × 720 相机帧上的冷启动定位(随机大小、±17° 旋转加任意直角朝向、透视、σ 0.8 模糊、噪声)和一次漂移跟踪的完整传输。
- `cpwin_tests`:经真实 `frame_render` 布局、2 / 3 个码面并排、整图定位的回环。
- 与 Python 参考实现对照(开发时一次性运行):渲染逐字节一致(两种配置、1–3 个码面、1 B–400 KB);在模糊 / 噪声 / 撕裂 / 摩尔纹码面上接受的单元与状态码一致;24 张合成 1080p 帧上定位角点与参考相差 ≤ 0.001 像素。
